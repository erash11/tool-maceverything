## Decisions, with the reasoning
- (b2) "cache sorted ids per query" was dropped for fast sorts (#20): a cache helps only page 2+
  and goes stale on every file event; a cached path order plus heap selection makes page 1 fast too.
- Path order changed to folder first, then names (`/a/z` before `/a b`), as in Everything (#20).
- `type:` text is the system's UTType description; unknown extension = "document" (#19). The app's
  Type and Extension columns use the same public helpers, so sorted columns read in order (#22).
- Every file action (keys, context menu, double-click, drag) takes only rows of the current
  search, checked when it runs (#24, #26): old rows stay on screen while a new search loads.
- After Move to Trash the app waits 1.5 s and searches again; not the daemon's `sync`, which
  drains a whole walk first (#24).
- The Trash counts as temp, so a trashed file leaves the results (#25, found by Eric's test).
- Rejected Codex findings: R7-F1 on #18 (Unicode case folding: belongs in `searchForm` for all
  searches); R21-F7 on #21 (a waiting Down dropped while the daemon restarts: a late focus jump
  would surprise).
- Up Arrow back to the box was left out: not sure Everything does it, so not a parity gap.
